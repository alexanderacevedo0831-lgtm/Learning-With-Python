Operational Data Validation & Analysis Tool
Overview:
    This project is a Python-based operational data validation and analysis tool designed to ensure the integrity and reliability of machine-generated weight data from industrial scales. It focuses on reducing human error, detecting faulty device output, and providing clear, actionable reporting for operations teams.

Problem Statement:
    Operational teams rely on accurate machine-generated data to make business-critical decisions. Inconsistent formatting, missing fields, and device anomalies can lead to incorrect reporting, financial errors, and poor decision-making. This tool enforces strict data contracts and surfaces issues early before they propagate downstream.

How It Works:
    The system ingests JSON-formatted records generated by industrial weight scales and processes them in three stages:

1. Data Validation:
    "Enforces a strict schema for all incoming records."
    "Validates timestamps (ISO 8601), metrics, numeric values, and fixed device identifiers."
    "Rejects invalid records while continuing to process valid data."
    "Treats empty input files as an explicit, reportable state."

2. Data Analysis:
    "Applies operational thresholds to detect abnormal weight values."
    "Flags WARN and CRITICAL events based on defined tolerances."
    "Identifies suspicious device behavior through repeated or unrealistic values."
    "Separates data integrity issues from operational anomalies."

3. Reporting:
    "Generates a human-readable, prioritized text report."
    "Highlights critical issues first."
    "Summarizes overall system health."
    "Clearly separates invalid records from valid operational data."
    "Provides context and suggested actions for troubleshooting."

System Health Logic
The system is considered UNHEALTHY when:
    "More than three CRITICAL events occur in a single day."
    "More than five invalid records are detected."
    "WARN events exceed a defined frequency threshold, indicating a recurring issue."

Design Principles:
    "Fail fast on structural errors."
    "Separate validation, analysis, and reporting concerns."
    "Optimize for operational clarity over raw data volume."
    "Scope intentionally limited to batch processing and reporting."

Intended Audience:
    This tool is designed for operations, infrastructure, and systems teams responsible for monitoring device outputs and maintaining data integrity in production environments.
